Help

Test with a harmless endpoint first. Each press (and each poll) sends a real request.

How it works
  • The key asks the Status URL (GET) every Every (ms) and shows On or Off from the answer. It never flips on its own.
  • Pressing while Off calls the On request; pressing while On calls the Off request. Then the key checks the status again and shows what the API reports.
  • Polling pauses while a press is being sent. A second press during that time is ignored.
State rules

The Expression reads a value from the status JSON (same syntax as the Webhook action, e.g. data.power). Leave it empty to use the whole response text, such as a plain on or off.

On when equals emptytrue, on, 1, yes (any case) = on. Anything else = off.
On when equals setOnly that exact value (any case) = on. Everything else = off. The defaults no longer apply.
No value at allShows NO VALUE instead of guessing.
Custom icons

Each state can use its own image instead of the default one. Choose where it comes from, then fill in the field next to it.

File on diskThe full path to a local .svg, .png, .jpg, .gif or .webp file, e.g. C:\icons\on.svg or /Users/you/icons/on.svg. Network (\\server\…) paths are not allowed. Changes to the file show up on the next poll.
Status responseAn expression on the status JSON that returns an image: SVG markup, or a data:image/…;base64,… URI (same as the Webhook action's Icon).
  • SVGs up to 256 KB and other images up to 512 KB. Scripts, external links and similar content are blocked in SVGs.
  • If the file is missing, or the response has no usable image, the default icon is used and the reason is written to the log.
  • The question mark for an unknown state and the warning for a failed poll can't be changed.

SquareOff
Check squareOn
Question markState not known yet (before the first successful poll, or no status URL)
WarningThe last poll failed. The reason is the title, and it clears on the next success.

Titles: HTTP 500, TIMEOUT, NO CONN, REDIRECT, BAD JSON, TOO BIG, ERR (expression failed), NO VALUE.

A press alerts if the key never learned its state, if the needed On/Off URL is empty, or if the request failed. After a warning the key still remembers the last known state, so a press works while the API is flaky.

Timeout, polling and redirects
  • Timeout (s): 1 to 120 seconds, used by all three requests. Empty or 0 = 10 s.
  • Every (ms): minimum 250. While polling, a request waits at most max(3 s, 3× the interval).
  • Redirects are never followed, so your headers, body and query string can't be sent anywhere else. Use the final URL instead.
Privacy

URLs, headers and bodies are saved as plain text in your Stream Deck profile and are included if you export or share it. Remove tokens first.
